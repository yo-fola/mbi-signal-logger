# 🔌 API

## What it does

The Express API validates reports, generates incident IDs, calculates analytical information, manages configuration and returns data to the three browser applications.

Local base URL: `http://127.0.0.1:3000`

IIS exposes the API through the public `/api/*` path.

## Endpoints

| Method | Route | Purpose |
|---|---|---|
| GET | `/api/health` | Returns backend and runtime-file health |
| GET | `/api/config` | Reads application configuration |
| PUT | `/api/config` | Updates application configuration |
| GET | `/api/audit` | Reads audit records |
| GET | `/api/admin/audit` | Admin alias for audit records |
| POST | `/api/audit` | Records supported UI/Admin activity |
| POST | `/api/rf-estimate` | Calculates an RF reference from station and GPS input |
| GET | `/api/incidents` | Returns Field incident views |
| POST | `/api/incidents` | Creates a Public or Field incident |
| PATCH | `/api/incidents/:id` | Updates an incident |
| DELETE | `/api/incidents/:id` | Deletes an incident |
| GET | `/api/public-incidents` | Returns Public incident views |
| GET | `/api/analysis/incidents` | Returns combined Public and Field views |
| GET | `/api/summary` | Returns a Field summary |
| GET | `/api/analysis/summary` | Returns a combined summary |
| GET | `/api/incidents/export.csv` | Exports Field incidents as CSV |
| GET | `/api/analysis/incidents/export.csv` | Exports combined incidents as CSV |

## Incident creation

When `POST /api/incidents` receives a valid report, the server:

1. Validates required values.
2. Checks the submission key for an existing report.
3. Identifies the report as Public or Field.
4. Generates a `PUB` or `INC` ID.
5. Calculates available GPS, distance, scoring and RF information.
6. Writes the report to the correct store.
7. Records supported audit activity.

## Implementation steps

1. Start the Node.js service.
2. Confirm `GET /api/health` works locally.
3. Configure IIS ARR to forward `/api/*` to `127.0.0.1:3000/api/*`.
4. Test the health route through IIS.
5. Submit one Public and one Field test report.
6. Confirm both appear in the appropriate API views.

## Important notes

- API responses use no-cache headers.
- New clients should rely on server-generated IDs.
- Protect write, update and delete routes before production use.
- KML is generated by the Admin frontend from its filtered dataset.
